# Обробка замовлень інтернет-магазину

Консольна програма на Java з Maven. Вона створює замовлення двох категорій, обробляє їх у двох потоках і зберігає успішні результати у спільному списку в пам'яті.

Потрібні JDK 17 або новіший і Maven 3.9+. Для першої збірки потрібен інтернет: Maven завантажить Lombok, JavaFaker і JUnit. В IntelliJ IDEA можна використати вбудований Maven.

## Запуск через IntelliJ IDEA

1. Розпакуй архів і відкрий кореневий `shop-orders/pom.xml` через File → Open як Maven-проєкт.
2. У File → Project Structure → Project SDK вибери JDK 17 або 21.
3. Дочекайся завантаження залежностей. За потреби натисни Reload All Maven Projects у вікні Maven.
4. У Maven вибери кореневий проєкт → Lifecycle → package.
5. Відкрий `order-threads/src/main/java/ua/shop/orders/threads/ShopApplication.java` та запусти метод `main` зеленою кнопкою.

Якщо `builder()` підкреслюється як помилка, перезавантаж Maven-проєкт і перевір Settings → Build, Execution, Deployment → Compiler → Annotation Processors → Enable annotation processing.

## Команди для запуску

Команди виконуються з папки `shop-orders`, де знаходиться головний `pom.xml`.

Збірка та тести:

```text
mvn clean package
```

Запуск у Windows через CMD або PowerShell:

```text
java -Dfile.encoding=UTF-8 --module-path "order-threads/target/order-threads-1.0.0.jar;order-threads/target/lib" -m shop.threads/ua.shop.orders.threads.ShopApplication
```

У Windows також можна відкрити `run.bat`. Він збере та запустить програму й залишить вікно відкритим. Команди `java` і `mvn` мають бути доступні в PATH. Якщо Maven доступний лише всередині IntelliJ IDEA, скористайся запуском з IDE.

Для Linux і macOS:

```text
sh run.sh
```

Для окремого запуску тестів:

```text
mvn test
```

## Сценарій програми

JavaFaker заповнює дані чотирьох замовлень електроніки та шести замовлень одягу. Для електроніки використовуються навушники, клавіатури та планшети; для одягу — світшоти, сорочки та спортивні штани. Товари створюються через Lombok Builder.

Додаткове замовлення №11 має кількість -1. Воно демонструє обробку винятку: повідомлення про помилку виводиться в консоль, а некоректне замовлення не зберігається.

Потік `electronics-worker` обробляє електроніку, а `clothing-worker` — одяг. Після завершення обох потоків програма показує кількість успішних замовлень, їхню сумарну вартість і замовлення одягу, відсортовані за номером.

Очікуваний підсумок — `Успішних замовлень: 10`. Ціни, характеристики й кількість товарів генеруються випадково. Повідомлення двох потоків можуть з'являтися в різному порядку. Дані зберігаються лише до завершення програми.

## Поділ на модулі

| Папка Maven-модуля | Назва Java-модуля | Вміст |
| --- | --- | --- |
| `order-processing` | `shop.processing` | Товари, замовлення, перевірка й обробка |
| `order-storage` | `shop.storage` | Спільне сховище `OrderRepository` |
| `order-threads` | `shop.threads` | `OrderWorker`, JavaFaker та `ShopApplication` |

`requires` задає залежності між Java-модулями, а `exports` відкриває пакети. Пакет `ua.shop.orders.processing.internal` не експортується, тому клас `OrderValidator` недоступний іншим Java-модулям.

`requires static lombok` означає, що Lombok потрібний під час компіляції. `requires transitive shop.processing` у модулі сховища робить моделі доступними модулям, які його використовують. `requires java.sql` потрібний бібліотеці SnakeYAML усередині JavaFaker; бази даних у програмі немає.

## Що пояснити на захисті

| Поняття | Пояснення та приклад |
| --- | --- |
| Узагальнення | `Order<T extends Product>` та `OrderProcessor<T extends Product>` працюють із різними товарами. `String` як тип товару компілятор не дозволить. |
| Наслідування | `Electronics` і `Clothing` наслідують спільні назву й ціну від абстрактного `Product`. |
| Builder | `@Builder` на конструкторах генерує послідовні виклики `.name(...).price(...).build()`, включно з параметрами для полів батьківського класу. |
| JavaFaker | Генерує назви, ціни, бренди, розміри та інші демонстраційні дані перед запуском потоків. |
| Лямбди | `() -> electronicsWorker.run()` передає роботу потоку; `filter(order -> ...)` відбирає одяг. |
| Посилання на метод | `this::handleOrder` запускає обробку кожного замовлення, `Order::getTotalPrice` отримує суму, `Order::getId` використовується для сортування. |
| Потоки | `start()` запускає окремий потік, `join()` чекає його завершення. Виклик `run()` без `start()` працював би в поточному потоці. |
| Синхронізація | Методи `store()` і `findAll()` мають `synchronized`, тому одночасний доступ двох потоків до одного сховища захищений. `findAll()` повертає копію списку. |
| Винятки | `OrderProcessingException` сигналізує про некоректні дані. `OrderWorker` перехоплює його через `try/catch` і переходить до наступного замовлення. |
| Контроль доступу | Внутрішній пакет не експортується. `OrderWorker` також має доступ лише в межах свого пакета. |

Узагальнення контролюють типи під час компіляції, а перевірки даних працюють під час виконання. Власний виняток є звичайним класом: Java не дозволяє узагальнені підкласи `Throwable`.

## Перевірки

У `src/test/java` є перевірки різних типів товарів, суми замовлення, неправильних значень, одночасного збереження 1000 замовлень, повернення копії списку та продовження роботи після помилки. Тести не входять до основної програми.

Перевірено збірку на JDK 17, проходження всіх 15 тестових перевірок і запуск Java-модулів на Java 17 та 21. Кількість успішних замовлень, загальна сума та сортування відповідають очікуваному результату.
