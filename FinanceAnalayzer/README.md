# Фінансовий аналізатор

Практична робота 2 за презентацією. Програма читає CSV із банківськими транзакціями, рахує баланс, визначає витрати та виводить текстові звіти. Виконані основні завдання і самостійна робота зі слайдів 7 та 17.

## Запуск через IntelliJ IDEA

1. Розпакуй архів.
2. Відкрий кореневий `pom.xml` через File → Open як Maven-проєкт.
3. У File → Project Structure → Project SDK вибери JDK 17 або 21.
4. Дочекайся завантаження залежностей Maven.
5. Відкрий `src/main/java/ua/study/finance/Main.java` та запусти `main` зеленою кнопкою.

Використовується вбудований Maven. Для першого завантаження Lombok і JUnit потрібен інтернет. CSV уже є в проєкті, тому сам аналіз працює без інтернету.

Якщо IDEA не бачить конструктор або методи `getAmount()`, перезавантаж Maven-проєкт і перевір Settings → Build, Execution, Deployment → Compiler → Annotation Processors → Enable annotation processing.

Для запуску тестів у вікні Maven вибери Lifecycle → test.

## Дані та результати

Файл `src/main/resources/pr2.csv` — копія [CSV з презентації](https://informer.com.ua/dut/java/pr2.csv). Він містить 26 транзакцій. Формат рядка без заголовка: `дата,сума,опис`. Дата записується як `dd-MM-yyyy`.

Додатна сума означає дохід, від'ємна — витрату. У вихідному CSV немає окремого стовпця категорії, тому для групування використовується опис: «Сільпо», «Аптека», «Бензин» та інші значення з файлу.

| Показник | Очікуваний результат |
| --- | --- |
| Загальний баланс | 153000 грн |
| Кількість транзакцій за січень 2024 | 13 |
| Найбільша витрата за січень 2024 | Інші витрати, 9100 грн |
| Найменша витрата за січень 2024 | Кав'ярня, 750 грн |
| Сумарні витрати за грудень 2023 | 33400 грн |
| Сумарні витрати за січень 2024 | 38800 грн |
| Категорія з найбільшими сумарними витратами | Подарунки, 16300 грн |

У списках окремих транзакцій витрати показані зі знаком мінус. У підсумках за категоріями та місяцями показана додатна сума витрачених грошей.

Для текстових діаграм одна `*` відповідає повній тисячі гривень. Наприклад, 2500 грн позначаються двома зірочками, а точна сума друкується поруч. Залишок менше 1000 грн окремою зірочкою не позначається.

Місяць для підрахунку задається в `Main` змінною `monthYear` у форматі `MM-yyyy`. Початок і кінець періоду задаються змінними `start` та `end`. Обидві межі включаються до періоду.

## Класи та їх призначення

| Клас | Призначення |
| --- | --- |
| `Transaction` | Модель із датою, сумою та описом транзакції. |
| `TransactionCSVReader` | Читання рядків із джерела через URL. Працює з локальними файлами та HTTP-джерелами. |
| `TransactionCSVParser` | Перетворення списку рядків CSV на список `Transaction` та перевірка формату. |
| `TransactionAnalyzer` | Розрахунок балансу, підрахунок за місяць, пошук витрат та групування сум. |
| `TransactionReportGenerator` | Виведення транзакцій, результатів аналізу та текстових діаграм. |
| `Main` | Послідовний виклик читання, аналізу та формування звітів. |

Усі Java-класи розташовані в пакеті `ua.study.finance`.

## Коротко для захисту

`@Data` у `Transaction` генерує гетери, сетери, `toString()`, `equals()` та `hashCode()`. `@AllArgsConstructor` генерує конструктор для трьох полів. Це використання Lombok замість ручного написання повторюваного коду.

`TransactionCSVReader`, `TransactionAnalyzer` і `TransactionReportGenerator` оголошені як `abstract`. Їхні методи є `static`, тому викликаються через назву класу. Наприклад: `TransactionAnalyzer.calculateTotalBalance(transactions)`. Об'єкти цих трьох класів не створюються, а список транзакцій передається аргументом.

Читання і розбір даних розділені. Метод `readLines()` повертає звичайні текстові рядки та не знає, що означають поля CSV. Метод `TransactionCSVParser.parse()` перетворює їх на транзакції. Для іншого формату можна створити інший парсер, зберігши читання рядків.

У `readLines()` застосовано `try-with-resources`: після читання `BufferedReader` і його вхідний потік закриваються автоматично.

Загальний баланс — сума всіх сум із початковими знаками. До кількості транзакцій за місяць входять і доходи, і витрати.

Метод `findTopExpenses()` спочатку відбирає від'ємні суми, потім сортує їх за зростанням і бере перші 10. Найбільша витрата має найменше числове значення: витрата -9000 більша за розміром, ніж -500. Якщо витрат менше десяти, повертаються всі наявні.

Для найбільшої та найменшої витрати спочатку відбираються витрати за заданий період. Якщо їх немає, метод повертає `null`, а звіт показує відповідне повідомлення.

Для підсумків використовується `Map`: ключ — категорія або місяць, значення — сума витрат. Категорії у звіті виводяться від найбільшої суми, а місяці — у хронологічному порядку.

Тести перевіряють читання CSV, незалежне читання текстових рядків, розбір даних, баланс, місяць і рік, десять найбільших витрат, межі періоду та підсумки за категоріями й місяцями.

Збірку перевірено на JDK 17, усі 16 тестів проходять. Також перевірено запуск на Java 21 без Lombok під час виконання та незалежність читання вбудованого CSV від поточної робочої папки.

## Завантаження на GitHub

Після розпакування створи репозиторій для цієї роботи та завантаж вміст папки проєкту: `pom.xml`, папку `src`, `README.md` і `.gitignore`. Кореневий `pom.xml` має бути в корені репозиторію.

У `.gitignore` виключені результати збірки `target`, налаштування IntelliJ `.idea` та файли `*.iml`. Ці файли не потрібні для відкриття і перевірки проєкту на іншому комп'ютері.
